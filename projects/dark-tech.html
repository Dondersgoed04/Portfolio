The project

Dark Tech is a physical installation in the form of a photo booth. A user takes a photo, after which AI transforms their face, for example making them look older. Sounds fun, but there is a catch.

Before the AI processes the photo, the user sees how much water this action costs. After confirmation, the photo is transformed and water is physically pumped from a fish tank to a 'data center' object.

Goal: make the invisible, tangible impact of AI visible.

The project translates an abstract concept, the water consumption of AI data centers, into something people can literally see and hear. Every AI transformation has a price.

What I built

I built the complete AI backend for this project, from the first test scripts to the production API that ran during the exhibition. Not all at once, but iteratively: first figure out whether something works, then make it production-ready.

Proof of concept — test scripts

  • capture.py — testing the webcam with OpenCV, making sure frame capture worked before connecting it to the rest.
  • utils_image.py — loading and inspecting images with PIL to understand the data format the model expects.
  • test_model.py — running the SD pipeline locally on GPU, isolated from the API, to validate the transformations worked.
  • main.py — tested the OpenAI API as an alternative, later dropped in favour of running the model locally.

Production backend

  • app.py — the complete Flask REST API with a /api/generate-photo endpoint that orchestrates everything: receive image, validate, run SD img2img on GPU (float16 for VRAM), route the transformation, return base64 response to the frontend, trigger the pump.
  • validator.py — Haar cascade version: brightness, resolution and face detection checks before sending to the model.
  • modules/validator.py — InsightFace version, more inclusive face detection, replaced the Haar cascade due to bias issues.
  • modules/face_utils.py — InsightFace integration: face detection and swap_face function.
  • modules/transformations.py — SD prompt dictionary for routing transformations (elderly, younger, etc.).

Technical choices

A deliberate choice was to run the model locally on a GPU instead of using an external API. This had two reasons:

  • Faster inference without network latency for the real-time installation.
  • Full control over the model and parameters (strength, steps, prompt).

Stable Diffusion 1.5 via the HuggingFace img2img pipeline was the right choice: it preserves the composition of the photo and only adjusts style and features based on the prompt.
